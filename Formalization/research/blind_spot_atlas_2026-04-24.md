# Blind-Spot Atlas — 2026-04-24

*Status: methodological research note. This atlas consolidates the first historical blind-spot audit into a reusable diagnostic map for ACP development. It does not add a theorem or reduction. Its purpose is to classify missing structure so that future cross-domain encounters generate sharper questions rather than vague analogy.*

## 1. Premise

A blind spot is not merely an unknown answer. It is a missing condition for asking the right question.

In ACP terms, a blind spot matters when a domain has enough structure to suggest the productive interval, drift, restraint, or generativity, but one of the required bridge objects cannot yet be typed. The failed or incomplete typing is the signal.

The first historical audit extracted the reusable signature:

> Stable regularities can precede the carrier, partition, or transformation vocabulary that makes them explainable.

This atlas turns that signature into a working diagnostic.

## 2. Blind-Spot Types

| Type | Missing object | Symptom | Historical model | ACP response |
|---|---|---|---|---|
| Hidden carrier | substrate that physically carries the pattern | regularity is measurable, mechanism is underdetermined | heredity before DNA | mark a carrier gap; do not overclaim mechanism |
| Hidden multiplicity | lower-level state-counting or ensemble structure | macro-observable works but lacks generative level | thermodynamics before statistical mechanics | treat operational thresholds as provisional; search for ensemble / microstate support |
| Hidden transformation | map between descriptions, levels, or scales | cross-domain regularity appears before its invariance operator | critical phenomena before RG | search for a functor, coarse-graining, or flow operator |
| Hidden partition | subsystem split needed to state coordination | boundary behavior exists but A.20 cannot be typed | no-partition systems / WI-E.3 | ask whether a partition is primitive, emergent, or generated |
| Hidden conservation law | invariant needed to justify transfer or floor | coordination appears present but no conserved quantity is named | pre-Noether mechanics as template | isolate kernel-preserving or mechanism-preserving quantity |
| Hidden observable | measurable domain-native proxy | mapping is narratively plausible but empirically elastic | semantic-field / language probes | choose observable before promoting beyond probe |
| Hidden falsifier | condition that could make the mapping fail | analogy explains everything after the fact | ornamental analogies | demote until a stress path exists |
| Hidden scope boundary | class where the current statement cannot apply | theory handles nearby cases but breaks on a precise domain | Type III / infinite-dimensional A.20 concerns | state boundary as open problem, not exception handling |
| Hidden normative filter | community standard that excludes the crucial question | field debates old frame while crisis requires new frame | crisis science / dominant paradigms | monitor downstream inquiry-space and OP-10 exposure |

These are not mutually exclusive. The important move is to name the dominant missing object, because different missing objects call for different next actions.

## 3. Diagnostic Questions

When a candidate domain almost maps to ACP, ask:

1. Is the regularity measurable before the carrier is known?
2. Does the observable work operationally while hiding a lower-level multiplicity?
3. Does the domain require a transformation between scales before the relevant object appears?
4. Is the partition missing, or merely not primitive at the current scale?
5. Is there a claimed coordination transfer without a stated conserved quantity?
6. Is the mapping missing a domain-native observable?
7. Is there any possible observation, simulation, or example that would falsify the mapping?
8. Does the domain reveal a boundary of the current ACP statement?
9. Is the field's own explanatory culture preventing the question from being posed?

If none of these questions bite, the domain may still be interesting, but it is not yet functioning as a blind-spot map.

## 5. Promotion Rules

Use the following rule of thumb:

- **Probe stays in `WHAT_IF.md`** when the blind spot is only gestured at.
- **Research note** when the blind spot can be classified and compared across examples.
- **Bridge note** when a missing object can be named as a candidate structure, such as a carrier, observable, functor, or conservation law.
- **Open problem** when the missing object becomes a proof obligation.
- **Reduction/theorem** only after the missing object is supplied and the mapping no longer depends on historical or analogical support.

The goal is not to promote ideas quickly. The goal is to avoid confusing a named blind spot with a solved one.

## 6. Working Heuristic: Ask What Would Have Made the Question Askable

For any present ACP gap, reconstruct a hypothetical future in which the gap has been solved. Then ask:

> What new object would that future version of the theory say we lacked?

Examples:

- If WI-E.3 is solved, the missing object may have been a partition-generating functor $\Pi$; the first candidate bridge shows that such a functor cannot be universal because primitive automorphism actions obstruct nontrivial invariant partitions.
- If OP-12 is solved, the missing object may have been a lower-level multiplicity or compression metric for theory evolution.
- If OP-11 is solved, the missing object may have been an empirical carrier of semantic distinction, not a philosophical definition of meaning.
- If OP-18 is solved, the missing object may have been an invariant translating physical mechanism preservation into kernel preservation.

This heuristic is deliberately retrospective in form. History shows that progress often looks, from the future, like the discovery of the object that made yesterday's confusion typeable.

## 8. Minimal Output Standard

Before a blind-spot mapping is considered useful, it should produce at least one of:

- a new named missing object;
- a domain-native observable;
- a falsification path;
- a sharper scope boundary;
- a candidate bridge structure.

If it produces only a satisfying analogy, it has failed the generativity check.
